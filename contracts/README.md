# Backend V2 contract snapshot

`level5-v2.openapi.json` is a **pinned** copy of Backend V2's canonical OpenAPI document
(`sweat-this/Level5Backend`'s `v2/openapi/level5-v2.openapi.json`), and `level5-v2.source.json`
records exactly which Backend revision it was pinned from:

```json
{
  "backendRepository": "sweat-this/Level5Backend",
  "backendRef": "<branch or tag the pull was run against>",
  "backendCommit": "<resolved commit SHA>",
  "canonicalPath": "v2/openapi/level5-v2.openapi.json"
}
```

Neither file is regenerated by the normal frontend build/test/lint - both are committed inputs.
Nothing in `npm run build`, `npm test`, or frontend CI ever reaches out to the Backend repository,
GitHub, or a running Backend V2 instance. Adopting a new Backend contract is a deliberate,
explicit developer action.

## Updating the pinned contract

From a local clone of `sweat-this/Level5Backend`:

```sh
scripts/contracts/pull-backend-contract.sh --backend-repo <path-to-Level5Backend-checkout> [--ref <git-ref>]
npm run contracts:generate
```

`--ref` defaults to that checkout's current `HEAD`. The script reads the file via `git show` (not
the working tree), so it's safe to point at any branch, tag, or commit without checking it out.

Review the resulting diff in `contracts/`, `contracts/level5-v2.source.json`, and
`src/generated/level5-v2.ts` like any other change, and commit them together.

## Generated TypeScript

`src/generated/level5-v2.ts` is generated from `level5-v2.openapi.json` via `openapi-typescript`
and is committed. It is never hand-edited.

```sh
npm run contracts:generate   # regenerate it from the pinned snapshot
npm run contracts:check      # fail if it's out of date relative to the pinned snapshot
```

`contracts:check` runs in CI. It only compares the two committed files to each other - it never
fails because Backend `dev` moved.
